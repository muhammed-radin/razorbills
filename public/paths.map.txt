1. ACCESS CONTROL ROLES & DEFINITIONS
----------------------------------------------------------------------------------------------------
- PUBLIC / ANONYMOUS VISITOR:
  Unauthenticated user accessing the site for the first time without an active session or cookies.
  Can browse public catalog and policy pages without restrictions.

- GUEST SESSION (ANONYMOUS AUTH):
  Temporary guest account generated via authClient.signIn.anonymous() when an unauthenticated
  user opts to continue without a formal login. Marked as `session.user.isAnonymous === true`.
  Permitted on all routes listed in `GUEST_ACCESS_PATHS` in App.jsx. Attempting to visit non-guest
  routes redirects the user to the home page ("/").

- REGISTERED CUSTOMER (AUTHENTICATED USER):
  User signed in with a validated customer account (Email/Password or Google OAuth).
  Has `isAnonymous === false` and `role !== "admin"`. Has full access to personal account
  sections, cart, checkout, order tracking, address book, wishlist, support, and settings.

- ADMINISTRATOR (ADMIN ROLE):
  Authenticated user with `role === "admin"`. Has exclusive access to the administrative
  backoffice under `/auth/admin/*`. Attempting to access admin routes by non-admins or
  unauthenticated visitors results in an immediate redirection to "/404" (security obfuscation).

- SEARCH ENGINE BOT / CRAWLER:
  Automated crawlers (Googlebot, Bingbot, etc.) regulated by `public/robots.txt`.
  Disallowed from visiting `/auth/`, `/admin/`, and `/auth/admin`. Allowed on general public routes.

----------------------------------------------------------------------------------------------------
2. ARCHITECTURAL GUARDS & ROUTING MECHANISMS
----------------------------------------------------------------------------------------------------
1. Hash Router Implementation:
   Defined via `createHashRouter` in `src/router/Router.jsx`.
   All frontend paths resolve in browsers with the hash anchor prefix (e.g., `/#/search`).

2. SessionLayout (Root Wrapper):
   All routes are wrapped in `UserSessionProvider` in `src/router/SessionLayout.jsx`, providing
   centralized session lifecycle management (`useUserSession()`).

3. App.jsx Route Guard (Customer & Storefront Routes):
   - `GUEST_ACCESS_PATHS`: ["/", "/search", "/categories", "/order-status", "/product/:id",
     "/login", "/signup", "/forgot-password", "/about", "/contact", "/return", "/shipping",
     "/privacy", "/terms"]
   - If an unauthenticated user visits a route NOT in `GUEST_ACCESS_PATHS` and NOT in `HIDE_CHROME_PATHS`,
     an "Authentication Required" confirmation dialog is displayed:
     * Clicking "Login" redirects to `/login`.
     * Clicking "Continue as Guest" creates an anonymous session.
   - If a user has an anonymous session (`isAnonymous === true`) and visits a route outside
     `GUEST_ACCESS_PATHS`, they are redirected to `/`.
   - `HIDE_CHROME_PATHS`: ["/login", "/signup", "/forgot-password"] suppresses Navbar, Footer, and
     Mobile Bottom Nav to present distraction-free authentication interfaces.

4. AdminAuth Guard (Admin Routes):
   - Defined in `src/pages/Admin/auth/page.index.jsx` wrapping `/auth/admin/*`.
   - Validates `data.user.role === "admin"`.
   - If unauthenticated, pending error, or not role "admin": silently redirects to `/404`.
   - Renders `AdminApp` layout (`src/pages/Admin/admin.app.jsx`) with sidebar and breadcrumbs only
     for authorized admin sessions.

5. Search Engine Directives (public/robots.txt & sitemap.xml):
   - `public/robots.txt` disallows: `/auth/`, `/admin/`, `/auth/admin`.
   - `public/sitemap.xml` indexes 16 primary consumer routes with priority and change frequencies.

5. AUDIT OBSERVATIONS & ARCHITECTURAL RECOMMENDATIONS
====================================================================================================

1. Route Alias Discrepancy in GUEST_ACCESS_PATHS:
   - In `src/App.jsx`, `/order-status` is included in `GUEST_ACCESS_PATHS`.
   - The alias `/order/status` defined in `src/router/Router.jsx` is NOT listed in `GUEST_ACCESS_PATHS`.
   - Recommendation: If guests need to access order tracking via `/order/status`, add `"/order/status"`
     to `GUEST_ACCESS_PATHS` in `src/App.jsx`.

2. Sitemap Consistency (Hash Routing vs Standard URLs):
   - In `dist/sitemap.xml`, URLs are written without hash anchors:
     `<loc>https://razorbills.vercel.app/search</loc>`
   - In `public/sitemap.xml`, URLs are written with hash anchors:
     `<loc>https://razorbills.vercel.app/#/search</loc>`
   - Search engine crawlers (e.g. Googlebot) typically ignore fragment identifiers (#). If static
     pre-rendering or HTML rewrites are used, standard path URLs without hashes are preferred for SEO.

3. Missing Public Pages in Sitemap:
   - The following public pages are currently omitted from `public/sitemap.xml`:
     * `/categories` (High SEO discovery value)
     * `/order-status`
     * `/checkout` (Optionally keep excluded from indexing)
     * `/support`
     * `/forgot-password`
   - Recommendation: Add `/categories` to `public/sitemap.xml` with priority 0.8 to improve catalog discovery.

4. Admin Route Protection Integrity:
   - Admin routes are protected on multiple layers:
     * Layer 1: robots.txt disallows crawlers from `/auth/`, `/admin/`, and `/auth/admin`.
     * Layer 2: Client-side guard `AdminAuth` checks session role and silently redirects unauthorized
       visitors to `/404`.
     * Layer 3: Backend API endpoints require valid JWT / session cookie with admin privileges.
